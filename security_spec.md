# ZF Accounting Cloud Vault — Security Specification (`security_spec.md`)

## 1. Data Invariants
1. **Global Default Deny All**: Top-level `match /{document=**} { allow read, write: if false; }` ensures any unmatched path or omitted operation is rejected by default.
2. **Master Owner / Verified Admin Authority & Non-Escalation**: Only verified users (`request.auth.token.email_verified == true`) matching the bootstrapped owner email (`rh.faysal007@gmail.com`) or an explicit `/admins/{uid}` document (which only the bootstrapped owner may create or update) may modify `role` or permission booleans (`canDeleteCustomers`, `canDeleteCommissionPersons`, `canChangeProfilePhoto`, `canChangeCommissionPersonPhoto`, `canDelete`, `canAddTransactions`, `canApproveInvoices`, `canExport`, `canViewLedger`, `canEditCustomers`, `canManageCommissions`, `canAddCommissionRecords`, `canEditCommissionRecords`, `canDeleteCommissionRecords`, `canPayCommissions`, `canImportCommissions`, `canManageCommissionMonths`, `canAddCommissionPersons`, `canEditCommissionPersons`, `canMergeCommissionPersons`, `canManageBazar`, `canManageBuyers`, `canManageBazarBuyers`, `isCommissionOnly`, `isCommissionBazarOnly`, `status`). Only the bootstrapped owner may create, promote, modify, or delete `'owner'` accounts. Regular users cannot escalate their own role or permissions in Firestore or Express API routes (including `/api/users/*` and `/api/sync/recover-if-empty`). `bazarBuyers` create/update/delete operations are restricted to the bootstrapped owner or active users explicitly granted `canManageBazarBuyers: true` via `/bazarBuyerDelegates/{email}`.
3. **Ownership & Workspace Membership Scoping**: Every document carries an immutable `ownerUid` strictly equal to `request.auth.uid` on creation. `transactions`, `customers`, `invoices`, `commissionPersons`, `commissionEntries`, `bazarBuyers`, and `homeBazarEntries` are scoped on both `get` and `list` by `ownerUid` or explicit workspace membership (`workspaceUserId`, `userId`, `linkedUserId`, `agentId`, `createdByUserId`, `delegateEmails`). Every `allow list` rule evaluates directly on `resource.data` without `get()` or `exists()` calls to prevent O(n) read amplification.
4. **Path ID Hardening**: Single-document read/write/delete operations validate document IDs with `isValidId(id)` (`size() <= 128` and `matches('^[a-zA-Z0-9_\\-]+$')`).
5. **Strict Keys & No Ghost Fields**: Every entity validation helper enforces `data.keys().hasAll(...)` and `data.keys().hasOnly(...)` on create and strict type/size/non-negative numeric bounds on both create and update. Updates additionally restrict mutated keys via `affectedKeys().hasOnly(...)`.
6. **Temporal Integrity & Immutability**: Every write validates `createdAt == request.time` on create, `createdAt == existing().createdAt` and `updatedAt == request.time` on update, and `incoming().ownerUid == existing().ownerUid`.
7. **PII Isolation**: User records (containing usernames and passwordHashes) and admin registry docs are gated behind `isBootstrappedOwner() || isAdmin()` and `resource.data.ownerUid == request.auth.uid`. Blanket `isSignedIn()` reads are forbidden.
8. **Terminal State Protection**: Cancelled invoices (`existing().status == 'Cancelled'`) and Cancelled commission entries (`existing().invoiceStatus == 'Cancelled'`) reject mutations unless overridden by `isAdmin()`.
9. **Bounded Arrays & Backend API Hardening**: Invoice `items` array is capped at `.size() <= 50` and validates element types when non-empty. Backend Express routes validate active sessions strictly without substring token spoofing, enforce `viewer`/`isCommissionOnly` and `canAddTransactions` restrictions, reject non-owner privilege escalation in `/api/sync/recover-if-empty`, and confine photo file writes/deletions inside the designated photos directory.

## 2. Adversarial Payloads ("Dirty Dozen" + Privilege/Workspace Checks)
Each payload below MUST return `PERMISSION_DENIED`:
1. **Unauthenticated Write**: Create `/users/usr_1` when `request.auth == null`.
2. **Unverified Email Spoof**: Create `/users/usr_2` with email `rh.faysal007@gmail.com` where `email_verified: false`.
3. **Non-Owner / Non-Member Read PII**: Read `/customers/cust_1` as an unrelated verified user (`other@example.com`) whose `uid` is neither `ownerUid` nor `workspaceUserId`.
4. **Blanket List Without Ownership or Workspace Filter**: Query `/transactions` as an unrelated verified user or without matching `ownerUid`, `workspaceUserId`, or `userId`.
5. **Identity Spoofing on Create**: Create `/transactions/tx_1` setting `ownerUid: "someone_else"` instead of `request.auth.uid`.
6. **Shadow / Ghost Field Injection**: Create `/users/usr_3` with an extra undeclared field `isSuperAdmin: true`.
7. **Path ID Poisoning**: Create `/customers/bad..id$poison` failing `^[a-zA-Z0-9_\\-]+$`.
8. **Temporal Forgery on Create**: Create `/homeBazarEntries/hb_1` passing a hardcoded past `createdAt` instead of `request.time`.
9. **Immortal Field Mutation**: Update `/transactions/tx_1` attempting to change `ownerUid` or `createdAt`.
10. **Value Poisoning on Update**: Update `/invoices/inv_1` setting `totalAmount: "99999"` (string instead of number) or oversized string `notes` (`> 2000` chars).
11. **Role Self-Escalation / Direct Admin Write**: Create `/admins/attacker_uid` by a non-admin user.
12. **Unbounded Array / Type Poisoning**: Create `/invoices/inv_2` with `items` containing 51 entries or a non-map element `[123]`.
13. **Regular User Self-Escalating Role or Permission Booleans**: Update `/users/usr_staff` as a non-admin regular user setting `role: "admin"`, `canDeleteCustomers: true`, `canDeleteCommissionPersons: true`, `canChangeProfilePhoto: true`, `canChangeCommissionPersonPhoto: true`, `canDelete: true`, `canAddTransactions: true`, or `canApproveInvoices: true`.
14. **Cross-Workspace Access on Commission & Bazar Collections**: Read or list `/commissionPersons`, `/commissionEntries`, or `/homeBazarEntries` as an unrelated verified user outside `ownerUid` and workspace membership fields (`workspaceUserId`, `userId`, `linkedUserId`, `agentId`, `createdByUserId`).
